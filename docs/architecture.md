 # ゲーム設計書

対象は「ぼくのかんがえたちょうさいきょうの武器（仮称）」のローカル試作品（MVP）です。ゲーム全体の構想は [企画書 v0.3](spec_v0.3.md) を参照してください。この設計書では、1台のブラウザで2人分の武器を作り、すぐに対戦して勝敗理由を読めるところまでを設計します。

**採用方針**は、FlaskとPythonを使い、外部AI APIなしで勝敗を決めることです。以下の属性セット、文字数、点数、確率、判定の優先順はすべて**仮仕様**です。試遊とテストの結果を基に調整します。

## 1. 技術構成

| 担当 | 技術と役割 | 採用理由 |
| --- | --- | --- |
| Webの入口 | Flaskでフォームを受け取り、入力を検証し、判定結果を画面に渡す | 入力から結果までを一つのPythonアプリで追える。後から同じアプリをPython対応のホスティングに置ける |
| 対戦ルール | Pythonの関数で、能力解析、相性、運、イベント、勝敗を扱う | Flaskを起動せずにテストできる。外部通信がなく、AI利用料も発生しない |
| 画面 | JinjaのHTMLテンプレートとCSSを使う。実況の段階表示やスキップを追加するときは少量のJavaScriptを使う | 勝敗の計算をPythonに集約し、画面の調整をブラウザ側で進められる |
| 調整項目 | 属性相性と特殊イベントをJSONで管理する | Python標準ライブラリで読み込める。設定だけの変更をGitの差分で確認できる |

MVPはフォームの送信1回で判定し、その応答で結果を表示します。再戦用の入力値は結果画面のフォームに引き継ぎます。試合データの永続保存が不要なため、データベースやアカウントなしで動かせます。将来の公開も、まずはこの同一端末対戦をブラウザから遊べる形にします。

## 2. 対戦処理の流れ

1. **入力を検証する。** 2人分の武器名、単一属性、特殊能力文を受け取る。仮仕様では三項目を必須にし、武器名は30文字、能力文は50文字までとする。解析には表記を整えた文字列を使い、画面には入力した文を表示する。
2. **能力を読み取る。** 能力の種類やタグ、解析状態を作る。仮仕様として、無条件の勝利保証などが明確なら爆散判定を優先する。片方だけなら相手の勝利、両方なら引き分けとし、その時点で試合を終了する。
3. **通常得点を計算する。** 属性、能力の基本点、能力相性、三種類の運を両者について求める。双方の相性を、加点前の同じ能力情報から評価する。通常得点の高い側を暫定勝者とし、同点は暫定引き分けとする。
4. **特殊イベントを最大1件適用する。** 通常得点と暫定勝敗を条件判定に使う。得点を補正した場合は得点から再判定し、勝敗を変更する場合はイベントの指定結果を採用する。
5. **結果と理由を返す。** Pythonが最終勝敗と出来事の順序を確定する。画面はその順序で定型文を表示し、演出があっても同じ結果を使う。

属性相性は、仮に炎・水・風の3属性から始めます。JSONには有利な側と不利な側の組を登録し、有利側に2点を与えます。逆向きの関係は同じ組から読み取り、同属性や未登録の組は互角（両者0点）とします。将来の複合属性も、企画書どおり独立した属性IDとして相性を定義できます。

## 3. 特殊能力の評価

### 能力の特徴を残す

自由記述の原文に加えて、解析結果に**主効果**と**タグ**を持たせます。主効果は「攻撃」「反射」「運操作」のような、能力が何をするかを示す分類です。タグは「直接攻撃」のような、相手との相性を調べるときに使う特徴です。MVPは短い言い回しに対応するルールで主効果を一つ選びます。条件や代償は、確認できるものを判定理由に残します。数値に反映する条件は、対応するルールを作ったものに絞ります。

| 入力例 | 読み取りと評価（仮仕様） |
| --- | --- |
| 「相手に体当たりする」 | 主効果は攻撃、タグは直接攻撃。基本点を得る |
| 「相手の攻撃を反射する」 | 主効果は反射。相手が直接攻撃タグを持つと相性で1点を得る。相手が反射や運操作なら相性は0点 |
| 「相手の攻撃を反射できない」 | 否定を考慮し、反射として扱わない。ほかに読み取れる効果がなければ未分類 |
| 「相手の月曜日を火曜日にする」 | 未分類。原文と基本点を残し、対戦結果には「自由枠の基本点」と表示する |
| 「一度だけ無敵になる」／「何があっても必ず勝つ」 | 前者は回数制限のある防御として基本点の範囲で扱う。後者は無条件の勝利保証として爆散判定の対象にする |

仮仕様では、**通常の能力も未分類の能力も基本点は1点**です。未分類でも共通の基本点が入り、ほかの判定で勝てます。未分類には相性や運操作の効果を発動するためのタグを付けません。複数の効果が書かれて主効果を決め切れない場合も、未分類として扱います。これにより、説明文の長さや単語の多さで得点を積み増す誘因を減らせます。爆散は、条件や否定を確認したうえで、禁止対象と明確に判断できる場合に限ります。

相性は「自分の主効果 × 相手のタグ → 補正点と理由」という小さなルールとして、文章の解析処理から分けます。MVPは**直接攻撃を受ける反射側に加点する相性1件**を扱います。仮仕様として相性加点は各武器につき最大1点で、反射が反射を呼ぶような連鎖は扱いません。後から「妨害は回復に有利」などの組を追加できます。同じ武器に複数の効果を持たせる場合は、その段階で効果の一覧と適用順を設計します。

## 4. 運の設計

| 項目 | 計算方法と点数（仮仕様） | 変わるタイミング |
| --- | --- | --- |
| 武器固有の運 | 表記を整えた武器名からSHA-256で安定した値を作り、各武器に0または1点を与える | 武器名や固有運の算出ルールを変えたとき |
| 能力による運補正 | 「自分の運を上げる」など、運に作用すると解析できた能力に1点を与える。ほかは0点 | 能力文や解析ルールを変えたとき |
| 試合ごとの乱数 | 各武器に0または1点を等確率で与える | 試合のシード値（乱数の出発点）を変えたとき |

三項目は結果の内訳にも別々に残します。MVPの運操作は固定の補正点として扱うため、サイコロの確率やイベント率には影響しません。名前を変えて固有運を引き直しても、この項目による点差は最大1点です。通常得点の仮仕様は、**属性点＋能力の基本点＋能力相性点＋固有の運＋能力による運補正＋試合ごとの乱数**です。

固有運の計算は、武器名を受け取り、定められた幅の点を返す一つの関数にまとめます。画数を使う場合はここだけを差し替えられます。その際は、かな・記号・異体字など画数が確定しない文字の扱いと、点数の幅を決めます。

試合のシード値から、運の抽選用とイベント抽選用にそれぞれ別の乱数の並びを作ります。これにより、実況の追加や片方の抽選手順の変更が、もう片方の抽選結果に波及しにくくなります。再現テストでは、入力、シード値、同じ版のルールと設定を使います。

## 5. 特殊イベント

| 種類 | 作用 | 仮のイベント例 | 抽選枠（仮仕様） |
| --- | --- | --- | --- |
| 演出のみ（`flavor`） | 実況に出来事を追加する | 審判がくしゃみをする。得点と勝敗はそのまま | 3% |
| 得点補正（`score`） | 指定した側に点を加え、勝敗を再計算する | 通常得点の差が1点のとき、劣勢側が覚醒して1点を得る | 1% |
| 勝敗変更（`outcome`） | 指定した結果で勝敗を確定する。通常得点は理由表示用に残す | 暫定勝者がいるとき、隕石が落ちて引き分けになる | 1% |

`data/events.json` の各イベントに、ID、種類、出現率、条件、効果、実況文を持たせます。出現率は各イベントの試合全体に対する抽選枠です。たとえば3%、1%、1%の順に設定している場合、試合ごとに1〜100から一度だけ抽選し、1〜3、4、5を各イベントに割り当てます。6〜100はイベントなしです。当たったイベントが条件を満たさない場合もイベントなしとし、再抽選はしません。たとえば覚醒の実際の発生率は、1%に「1点差の試合の割合」を掛けた値になります。爆散で終了した試合は抽選の対象外です。

MVPの条件は「常に有効」「通常得点の差が指定値」「暫定勝者がいる」から選びます。効果は「実況行を追加」「劣勢側へ加点」「引き分けに変更」を用意します。同じ条件と効果を使うイベントはJSONの1項目で追加できます。新しい種類の処理が必要になったら、Pythonに対応する処理を追加します。設定読み込み時にはIDの重複、未対応の条件や効果、種類と効果の組み合わせ、確率が0〜100の整数か、合計が100%以内かを確認します。0%で個別に無効化できます。ひとまず合計5%の例から試し、特に勝敗変更の頻度を試遊で調整します。

## 6. データ構造とフォルダ案

以下の名前は実装時の目安です。MVPはPythonのデータクラス（関連する値に名前を付けてまとめる仕組み）と辞書で表現できます。

| データ | 主な項目 |
| --- | --- |
| 武器入力 | 武器名、属性ID、特殊能力の原文 |
| 能力解析結果 | 解析状態（分類済み／未分類／爆散対象）、主効果、タグ、確認できた条件や代償、判定理由 |
| 得点内訳（各武器） | 属性点、能力の基本点、能力相性点、固有の運、能力による運補正、試合ごとの乱数、イベント補正 |
| イベント設定 | イベントID、種類、出現率（%）、条件とその値、効果とその値、実況文 |
| 対戦結果 | 通常得点の内訳、暫定勝敗、得点補正があれば補正後の得点、最終勝敗、イベントID、順序付きの実況・勝敗理由、再現用シード値 |

| 場所 | 実装時の役割 |
| --- | --- |
| `app.py` | Flaskのフォーム受け付けと画面表示 |
| `game/abilities.py` | 自由記述を解析し、能力の特徴を返す |
| `game/battle.py` | 能力相性、運、イベントを評価し、対戦結果を返す。固有運は独立した関数にする |
| `data/` | `elements.json` に属性相性、`events.json` に特殊イベントを置く |
| `templates/`・`static/` | 入力・結果画面、CSS、仮のドット絵 |
| `tests/` | Flaskを起動せずに判定ルールを検証するテスト |

爆散で試合が終了した場合は、通常得点・暫定勝敗・イベントIDを空にし、最終勝敗と爆散の理由を返します。

## 7. MVPの範囲と実装順

MVPの完成条件は、**同じ端末で2人分の武器を作り、勝者または引き分けと、その理由を確認し、入力を引き継いで再戦できること**です。仮の3属性、短い能力解析ルール、反射の相性1件、三種類の運、三種類のイベント処理と各1件の設定で、この流れを確認します。ビジュアルは固定の仮素材、実況は短い定型文から始めます。ドット絵パーツの自動合成、画数、複数効果の連鎖、複合属性、公開・オンライン対戦、履歴やランキングは後続段階の候補です。

1. 固定の武器データで通常得点と勝敗理由を返す。反射と直接攻撃、反射と非攻撃、未分類の基本点、否定付きの能力、双方爆散を例にテストする。
2. 三種類の運とイベントを追加する。固定シードで再現性を確認し、固定した抽選値で各イベントの境界、条件不成立時、高得点側が引き分けになる場合を確かめる。多数試合では、左右の入力順による勝率の偏りとイベントの実際の発生率を集計する。
3. Flaskの入力・結果画面をつなぐ。異常な入力から戻れること、勝敗理由が最終結果と一致すること、再戦時に新しいシード値を使うことを確認する。
